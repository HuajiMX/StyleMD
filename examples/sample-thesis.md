# 绪论

Markdown 编辑器在导出 PDF 时，对自定义样式的支持普遍不足：要么只能用默认版式，要么需要用户手写 CSS。StyleMD 的目标是把「样式管理」做成可视化操作，让排版这件事回到可点击、可预览、可复用的轨道上。

::: abstract
本文说明 StyleMD 样式模型的组织方式：结构角色如何划分、样式如何继承、渲染后端如何与模型解耦。
:::

::: keywords
Markdown；样式管理；分页排版；PDF 导出
:::

## 研究背景

现有工具大致分两类。一类把样式写死在主题文件里，用户改一个标题字号需要读 CSS；另一类把样式交给排版引擎的模板语言，例如 LaTeX 的 `.tex` 模板，学习成本更高。

> 关键判断：真正稀缺的不是"能不能自定义"，而是"能不能在不写代码的前提下自定义，并且看到的就是最终结果"。

### 常见做法对比

下面用列表概括三类主流方案的能力边界：

- 主题 CSS 方案：灵活，但需要理解 CSS 选择器与盒模型
- 模板语言方案：排版能力强，但需要安装庞大的工具链
- 可视化样式面板：门槛最低，前提是样式模型设计得足够干净

1. 第一步：把 Markdown 解析成带语义角色的结构
2. 第二步：把角色映射到样式，展开继承链
3. 第三步：编译成 CSS，交给同一个引擎预览与导出

## 样式属性范围

表 1-1 列出了原型阶段已经支持的样式维度。

| 维度 | 可控项 | 落地方式 |
|:-----|:-------|:---------|
| 字体 | 字体族、字号、字重、倾斜、颜色 | `font-*` 系列属性 |
| 段落 | 对齐、行距、段前段后、首行缩进 | `text-align` / `line-height` / `margin` |
| 边框底纹 | 四边线型线宽、圆角、底纹色、内边距 | `border-*` / `background` / `padding` |
| 页面 | 纸张、方向、页边距、页眉页脚 | `@page` 规则 |

## 代码与公式

行内代码写作 `build(markdown, theme)`，代码块如下：

```ts
const result = build(markdown, theme)
document.write(result.html)
```
