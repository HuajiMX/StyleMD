# 表格上下文选项卡（表格工具）

日期：2026-10-09 ｜ 关联：AGENTS.md「表格上下文选项卡」、架构约束 8、`docs/plans/no-commit.png`（Word「表布局」布局参考）

## 目标

光标落在表格结构里时，在功能区选项卡栏右侧冒出一个**上下文选项卡「表格」**并自动聚焦过去；光标离开
就把它收起来并回到「开始」。选项卡里按五栏组织表格的常见调整：

| 栏目 | 内容 |
|:---|:---|
| 大小 | 宽度（按内容 / 撑满 100% / 百分比）、最小宽度（%）、最小高度（pt）、分布列、分布行 |
| 布局 | 一块面板 +「表头 / 内容」切换键：九宫格单元格对齐（左中右 × 上中下）+ 内边距 |
| 边框 | 预设（无边框 / 仅外框 / 全部网格 / 三线表）+「应用于」某一类边框后改线型 / 粗细 / 颜色，外加「边框和底纹…」完整窗口 |
| 样式 | 表头 / 内容单元格的样式窗口入口 + 两处底纹色 |
| 属性 | 跨页重复标题行开关、表格整体对齐（左 / 中 / 右） |

## 决策与取舍

| 待定项 | 选择 | 理由 |
|:---|:---|:---|
| 选项卡位置 | 功能区选项卡栏里、常规选项卡**右侧**，与 Word「表布局」同一个位置逻辑 | 选项卡的内容就是工具带上的控件组，只能挂在功能区；底部状态栏只有 30px 高，放不下五栏 |
| 出现与聚焦 | 光标进表格（`table` / `table.header` / `table.cell`）→ 出现并自动选中；离开 → 隐去，若当时选中的是它则回到「开始」 | 与 Word 的上下文选项卡一致；只认"进/出"这次状态变化，在表格里上下挪光标不会把用户手动切走的那一页又抢回来。表题（`table.caption`）不算表格结构，光标停在表题上不弹工具 |
| 整体版式的数据落点 | 新增 `document.table`（`TableSpec`），`schemaVersion` 3 → 4 | 宽度、最小尺寸、均分行列、跨页表头、整体对齐是"表格这个对象"的几何属性，不是文字样式；Word 的表格属性也是独立于段落样式的一层，将来 DOCX 后端能 1:1 映射。单元格级的（对齐、内边距、边框、底纹）仍旧落在 `table.header` / `table.cell` 角色，整表框线落在 `table` 角色 |
| 九宫格的竖轴 | `ParagraphSpec.verticalAlign`（top / middle / bottom），横轴复用 `paragraph.align` | 九宫格本来就是"段落对齐 × 垂直对齐"；默认 `top` 不写声明（基座规则 `[data-role="table-header"], [data-role="table-cell"] { vertical-align: top }` 已经兜住），换了值才写 `vertical-align`，免得二十多个角色块各多一行废声明 |
| 列对齐与样式对齐的关系 | Markdown 的列对齐仍是内容级直排（居中 / 右对齐写行内样式），但**左对齐不再写成行内样式** | `|:---|` 与 `|---|` 渲染等价（左对齐就是默认值），写成行内样式会把样式包里的单元格对齐在最常见的左对齐列上变成死的——那一栏也就白做了。居中 / 右对齐的列保持内容优先 |
| 宽度的单位 | 一律相对纸张内容区：`widthMode: full` = 100%，`widthPercent` ∈ (1, 100]，`minWidthPercent` ∈ [0, 100] | 用户要的是"不超过纸张内容区宽度"；编译成 CSS 的 `%` 后，分页器与导出都按内容区算 |
| 整体对齐的落法 | `margin-inline: auto` / `margin-inline-start: auto` | `width: auto` 的表格是 shrink-to-fit 的，auto 外边距就能左 / 中 / 右摆；`text-align` 是给单元格内容用的，不能借用 |
| 最小高度的落法 | 写在 `table` 上的 `height`（单位 pt） | CSS 里表格的 `height` 就是"最小高度"：多出来的高度由各行分摊，正好对上 Word 的"行高不足时整表撑高" |
| 分布列 | `table-layout: fixed` + 等宽 `<colgroup>`，分页器再把列宽按目标表宽标定成 px | 等宽列表在静态 HTML（CLI 输出）里也成立；分页切片只带行不带 colgroup，列宽必须落到单元格上才对齐（沿用原有做法） |
| 分布行 | 分页渲染前置量：副本里量出最高的一行，把所有行顶到同一高度 | "各行等高"要量才知道高多少，静态 HTML 里量不到。预览与导出 PDF（都走 Paged.js）生效，CLI 直接输出的静态 HTML 保持自然行高 |
| 跨页重复标题行 | 关掉时首行**不进 `<thead>`**（单元格角色不变） | Paged.js 只按 `<thead>` 决定要不要给续页补表头；不进 thead 就不补。默认开启，与旧版渲染逐像素一致 |
| 格线（共用边） | 格线单独一组数据：外框四条 = `table` 角色的 `border`，表头下线 = `table.header.border.bottom`，内部横线 / 内部竖线 = `table` 角色的 `grid`（`TableGridSpec`） | 单元格紧密堆积，相邻单元格**共用**一条边（左边格子的右边框与右边格子的左边框是同一条线）。四条边各写各的会在折叠边框模型里按"样式优先级 → 比粗细"打架，「给某一条边单独设虚线」就落不了地。编译时让每个单元格只画右边和下边、最后一行 / 最后一列不画（交给外框），每条共用边只声明一次；`core` 的 `tableGridOf` 是唯一读法，旧样式包把格线写在 `table.cell` 四边上时按"右边框当竖线、下边框当横线"兜住 |
| 边框 UI 的语义 | 操作对象是**边**（七条），线型 / 粗细 / 颜色是"手里这条线"，改它不动表格 | 仿 Word：换线型不该顺手把现有四条边一起换掉，得点预设或点某一条边才应用（那条边没线就刷上手里的线，有线就撤掉）；"先关掉旧的上框线再点开"就是改这条边的样式。窗口里的预览图就是真表格（表头 + 两行数据），画的正是共用边逻辑 |
| 布局的面板 | 表头与内容**共用一个面板**，上面一排「表头 / 内容」切换键决定改哪一类 | 两边要设的东西完全一样（九宫格 + 内边距），摆两块一样的面板只是把工具带撑宽；切换键带 `aria-pressed`，谁被选中一眼看得见。九宫格按钮的无障碍名仍是「表头左上 / 内容右中」，切换后仍然指得清 |
| 切换键的排布 | 竖着排成一列（`.seg.vertical`） | 做成一枚"面板选择器"的观感，跟右边的九宫格、内边距分开得更清楚，也省一条横向空间 |
| 控件的对齐 | 只修预设胶囊：`.border-dialog .field-chip.preset-chip` 覆盖 `.field-chip` 的 `align-items: baseline` | `.field-chip` 的基线对齐会把图标压到文字基线上，看着就是"图标没跟文字对齐"。**表单标签不定宽**——工具带本来就紧，控件按各自宽度排更紧凑（试过定宽 62px 对齐左边缘，撤掉了） |
| 窗口里的解释性小字 | 各分区的 `note`、表头副标题、底纹行的说明、预览下面那段格线解释全部删掉；只在「边框线」那一栏留一句「选择样式后在下方预览中点击对应边框以刷上样式」 | 表单本身已经说明了自己（预设按钮上有图标 + 文字、方向键上写着上/下/左/右、边线开没开用强调色表示），再铺一层说明文字只会把窗口撑大、把真正要操作的控件挤下去。操作顺序那句话留一条就够——它说的是「先选样式、再点边」这个顺序，光看控件看不出来 |
| 各窗口的默认尺寸 | 按表单内容收窄：边框窗口 700 → **500**、页眉页脚 720×360 → **560×279**、样式窗口 1000 → **380**（并撤掉「常用字体」那排快捷按钮——它是那一页最宽的一行）、配色窗口 980 → **900**；下限同样按内容给（470 / 480 / 380 / 660），**CSS 里不再写 `min-width`** | 表单其实用不到那么宽：边框窗口的内容自然宽 410、页眉页脚 534，窗口却固定 700 / 720，右边空出一条（页眉页脚还空掉一大半高度）。尺寸（含下限）统一由 `useDialogFrame` 给——CSS 里那条 `.style-dialog { min-width: 560px }` 会把 JS 设的 500 顶回去，两处各压一个下限只会互相打架。页眉页脚与边框窗口的高度也改成贴着内容量（与样式窗口同一套），删掉解释小字后它们本来就矮了一截 |
| 字号与字形一行 | 「字形」（倾斜 / 下划线）从单独一行挪进「字号与字形」这一行，做成与字号 / 字重 / 字距一样的 `Field`；**不加**加粗按钮 | 它是同一组的第四个设置项，用裸 `<span className="field-label">` 单独占一行，跟旁边三个「标签: 控件」长得不一样（用户原话：格格不入）。加粗没另开按钮也不是缺项——它就是左边的「字重」，再放一个 B 反而跟那个下拉抢同一件事（功能区那个 B 是同一字段的快捷开关，窗口里不必重复） |
| 一排按钮的 `Field` 外圈 | `Field` 加一个 `as="label" \| "span"`，默认仍是 `label`；「字形」这种里面是一排**按钮**的传 `span` | `Field` 默认渲染成 `<label>`（点标签能把焦点送进输入框，很多 `getByLabel('纸张')` 靠的就是它）。但里面放按钮时，浏览器会把这一排里的**第一个**按钮当成"标签对应的控件"，`:hover` 会从标签传播到它——鼠标移到「下划线」上，「倾斜」也跟着亮起 hover 底色，看着像两个开关一起被选中（e2e 有断言守着）。按钮自己带 `aria-label`，本来也不需要外圈当标签 |
| 样式窗口的页签 | 表格类结构（`table` / `table.header` / `table.cell`）**不显示「边框与底纹」页**；「编号」页只给 1–6 级标题 | 表格的线已经归「表格」选项卡按边设（相邻单元格共用一条边），样式窗口里那套"四条边各自独立"的表单对它们只会误导——与其在里面写一段指路说明，不如把页收起来（底纹与内边距在「表格」选项卡的样式 / 布局栏里有）。编号只有标题用得上，其余结构显示一个用不了的页只是噪声；顺带把计数器从 1–3 级扩到 1–6 级，让开放出来的页真能用 |
| 结构画廊的内容 | 表格 / 表头单元格 / 表格单元格**不再摆进「开始」页的结构画廊**；「表格」选项卡的样式栏补一个「表格样式…」入口 | 光标进表格就自动切到「表格」选项卡，外框、格线、九宫格对齐、内边距、底纹都在那一页，画廊里再摆三张卡片是重复入口（页眉页脚同理由「页面」页承担，早就没摆）。**`table` 角色并没有被架空**：外框四条边、字体基线、段前段后间距、分页控制仍写在它身上，所以样式栏留一个「表格样式…」窗口入口；表头 / 内容单元格的字体、字号、底纹则在它们的样式窗口里（从同一个样式栏进）。表题（`table.caption`）是普通段落，照旧留在画廊 |

## 已知限制与后续

- **分布行只在分页渲染里生效**：预览与导出 PDF（都跑 Paged.js）会把各行顶到等高，CLI 直接输出的静态
  HTML 保持自然行高——静态 HTML 里没有量行高的时机。
- **表格版式是文档级的**：Markdown 没有逐表属性的位置，五栏里的设置对整篇文档的所有表格生效。
  将来若要做"只改这一张表"，得先给语法加扩展（容器指令），那是另一件事。
- **三线表的粗细在 85% 预览里看不出来**：Chromium 折叠边框模型会把边框宽度按缩放后取整，
  1.5pt 与 0.75pt 在 85% 缩放下都画成 1px；导出 PDF（100%）正常。e2e 量粗细前先把预览调到 100%。
- **列为居中 / 右对齐的单元格不受样式包的对齐影响**：那是内容直排，优先级高于样式包（有意如此）。
- **单元格角色的四边不再各画各的**：`table.cell` / `table.header` 的边框由格线块统一接管
  （外框四条、表头下线、内部横线 / 竖线）；旧样式包写在单元格四边上的值仍按"右边框当竖线、
  下边框当横线"兜底，左 / 上两条由相邻单元格的线代表。表格类结构的样式窗口因此不再显示
  「边框与底纹」页——底纹与内边距在「表格」选项卡的样式 / 布局栏里改。
- 内置预设没有改渲染：表格版式的默认值（按内容宽度、左对齐、跨页重复标题行）与原行为一致。
